# §1 三分钟路径(老用户)

```bash
python3 --version    # 3.11+
docker --version
claude --version     # Claude Code v1.0+
```

```bash
cd /path/to/youzi-init-project
./install.sh install
```


# §4 三模式详解

## 4.1 三种模式对比

| 维度     | admin                             | server           | ui         |
| -------- | --------------------------------- | ---------------- | ---------- |
| 后端     | ✅                                | ✅               | ❌         |
| 前端     | ✅                                | ❌               | ✅         |
| 中间件   | ✅ (PostgreSQL + Redis + adminer) | ✅               | ❌         |
| 自动迁移 | ✅                                | ✅               | ❌         |
| 默认端口 | 8000 / 3000 / 8080                | 8000             | 3000       |
| 默认账号 | admin + 随机密码                  | admin + 随机密码 | —          |
| 典型场景 | 新建完整管理系统                  | 已有前端,要后端  | 接已有后端 |

## 4.2 配置 `.env`

**后端** `backend/.env`:

| 变量                       | 说明                   | 默认                            |
| -------------------------- | ---------------------- | ------------------------------- |
| `SECRET_KEY`               | JWT 签名密钥(≥32 字符) | `init.py` 生成时写入(随机64hex) |
| `DEBUG`                    | 调试模式               | `false`(生产必须 false)         |
| `POSTGRES_*`               | 数据库连接             | `<project_name>`                |
| `REDIS_HOST/PORT/PASSWORD` | Redis 连接             | `localhost:6379`                |
| `CORS_ORIGINS`             | 允许的跨域来源         | `localhost:3000`                |
| `JWT_EXPIRE_MINUTES`       | Token 过期(分钟)       | `60`                            |

**前端** `frontend/.env.development` 和 `.env.production`:

| 变量                | 说明                                         |
| ------------------- | -------------------------------------------- |
| `VITE_API_BASE_URL` | 后端 API 地址(默认 `/api/v1`)                |
| `VITE_APP_TITLE`    | 页面标题                                     |
| `VITE_PROXY_TARGET` | dev proxy 目标(默认 `http://localhost:8000`) |
| `VITE_TOKEN_KEY`    | localStorage token key(默认 `access_token`)  |

## 4.3 进阶用法

### 改项目名 / 显示名

项目名是 `init.py` 时一次性决定的（也是 Docker 容器名/卷名/PATH 关键路径）。
**不建议直接改 .env 改项目名**——重命名要改 8 处地方：

```bash
# 推荐：删了重跑（项目未提交代码时可这样）
rm -rf my-app
python3 /path/to/youzi-init-project/scripts/init.py new-name --only admin
```

显示名（页面标题）随时可改：

```bash
# 编辑 .env.development 和 .env.production
# macOS（BSD sed）:
sed -i '' 's/VITE_APP_TITLE=.*/VITE_APP_TITLE=我的商城/' my-app/frontend/.env.development
sed -i '' 's/VITE_APP_TITLE=.*/VITE_APP_TITLE=我的商城/' my-app/frontend/.env.production
# Linux / WSL / Git Bash（GNU sed，去掉 ''）:
# sed -i 's/VITE_APP_TITLE=.*/VITE_APP_TITLE=我的商城/' my-app/frontend/.env.development
# sed -i 's/VITE_APP_TITLE=.*/VITE_APP_TITLE=我的商城/' my-app/frontend/.env.production
# 或直接用编辑器修改文件
```

### 复用项目作为新模板

```bash
cp -R my-existing-app ~/templates/admin-base
# 改 ~/templates/admin-base 后用它 init 新项目
```

### 集成 CI/CD

```yaml
# .github/workflows/scaffold.yml
name: Scaffold new project
on: { push: { tags: ["v*-scaffold-*"] } }
jobs:
  scaffold:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: { python-version: "3.11" }
      - run: pip install jinja2
      - run: python scripts/init.py my-new-app --only admin
      - uses: actions/upload-artifact@v4
        with: { name: my-new-app, path: my-new-app/ }
```

### 改模板

直接编辑 `templates/backend/app/models/base_class.py` 等文件 — 符号链接模式下**自动生效**,不需要 reinstall。

## 4.4 生产部署清单

```bash
cd my-app/backend

# 生成全新强密钥并替换(覆盖,不是 append)
SECRET_KEY=$(openssl rand -hex 32)
# macOS（BSD sed，必须有 ''）:
sed -i '' "s|^SECRET_KEY=.*|SECRET_KEY=${SECRET_KEY}|" .env
# Linux / WSL（GNU sed，不要 ''）:
# sed -i "s|^SECRET_KEY=.*|SECRET_KEY=${SECRET_KEY}|" .env

# 关闭调试
sed -i '' 's/^DEBUG=.*/DEBUG=false/' .env   # macOS
# sed -i 's/^DEBUG=.*/DEBUG=false/' .env   # Linux

# 用托管 DB / Redis（填生产 URL）
sed -i '' 's/^POSTGRES_HOST=.*/POSTGRES_HOST=db.prod.example.com/' .env
sed -i '' 's/^POSTGRES_PASSWORD=.*/POSTGRES_PASSWORD=your-prod-pwd/' .env
# sed -i 's/^POSTGRES_HOST=.*/POSTGRES_HOST=db.prod.example.com/' .env  # Linux

# 跑迁移(确保之前已跑过 `make db-migrate msg="init"` 建基线)
alembic upgrade head

# 启动(gunicorn + uvicorn worker,已在 pyproject deps 里)
gunicorn app.main:app -w 4 -k uvicorn.workers.UvicornWorker -b 0.0.0.0:8000
```

**Docker 化部署**(推荐):

```bash
cd my-app
docker compose --env-file backend/.env up -d --build
```

前端:

```bash
cd my-app/frontend
pnpm build    # 产物在 dist/,挂 Nginx 即可
```

**安全清单**:

- [ ] 修改默认 admin 密码

- [ ] `DEBUG=False` / `DB_ECHO=False`
- [ ] `CORS_ORIGINS` 只保留可信域名

# §5 加业务模块 (`add_module.py`)

## 5.1 命令

```bash
python3 backend/scripts/add_module.py <name> [选项]
```

| 参数 / 选项      | 默认值     | 说明                                      |
| ---------------- | ---------- | ----------------------------------------- |
| `name`           | 必填       | 模块名,snake_case,如 `order` / `product`  |
| `--title`        | 由 name 推 | 中文标题(菜单 / 路由 / 接口 summary)      |
| `--fields`       | `name:str` | 自定义字段,见 [§5.2](#52-字段语法)        |
| `--backend-dir`  | `backend`  | 后端目录                                  |
| `--frontend-dir` | `frontend` | 前端目录                                  |
| `--force`        | 关         | 强制覆盖已存在文件(默认拒绝,保护你的手改) |

## 5.2 字段语法

```
name:type[:default]
```

| 段   | 必填 | 说明                                                   |
| ---- | ---- | ------------------------------------------------------ |
| name | ✅   | 小写字母 / 下划线开头,仅字母数字下划线                 |
| type | ✅   | `str` / `text` / `int` / `float` / `bool` / `datetime` |
| def  | ❌   | 默认值;**省略 = 必填 (nullable=False)**                |

### 5.2.1 类型映射

| 类型       | SQLAlchemy       | Pydantic   | TS        | 表单控件            |
| ---------- | ---------------- | ---------- | --------- | ------------------- |
| `str`      | `String(100)`    | `str`      | `string`  | `el-input`          |
| `text`     | `Text`           | `str`      | `string`  | `el-input textarea` |
| `int`      | `Integer`        | `int`      | `number`  | `el-input-number`   |
| `float`    | `Numeric(10, 2)` | `float`    | `number`  | `el-input-number`   |
| `bool`     | `Boolean`        | `bool`     | `boolean` | `el-switch`         |
| `datetime` | `DateTime`       | `datetime` | `string`  | `el-date-picker`    |

### 5.2.2 默认值写法

| 场景         | 写法                | 解析后             |
| ------------ | ------------------- | ------------------ |
| 必填(无默认) | `name:str`          | `nullable=False`   |
| str 默认     | `status:str:active` | `default='active'` |
| int 默认     | `stock:int:0`       | `default=0`        |
| float 默认   | `price:float:9.99`  | `default=9.99`     |
| bool 默认    | `enabled:bool:true` | `default=True`     |

str 默认**不需要写引号**;写了也行(`status:str:'active'` ✅)。

### 5.2.3 禁止的字段名

- 保留名:`id` / `created_at` / `updated_at`(由 TimestampMixin 自动生成)
- Python / JS 关键字:`class` / `type` / `import` / `return` 等
- 非法字符:含 `;` `"` `'` ` ` 等任何非 `[a-z0-9_]` 字符

## 5.3 完整示例:商品模块

```bash
python3 backend/scripts/add_module.py product \
    --title "商品管理" \
    --fields "name:str,price:float:0,stock:int:0,status:str:active,desc:text"
```

生成 6 个文件:

**`backend/app/models/product.py`**:

```python
"""商品管理 ORM 模型。"""
from sqlalchemy import Integer, Numeric, String, Text
from sqlalchemy.orm import Mapped, mapped_column
from app.models.base_class import Base, TimestampMixin

class Product(Base, TimestampMixin):
    __tablename__ = "products"
    id: Mapped[int] = mapped_column(Integer, primary_key=True, autoincrement=True)
    name: Mapped[str] = mapped_column(String(100), nullable=False)
    price: Mapped[float] = mapped_column(Numeric(10, 2), default=0.0)
    stock: Mapped[int] = mapped_column(Integer, default=0)
    status: Mapped[str] = mapped_column(String(100), default='active')
    desc: Mapped[str] = mapped_column(Text, nullable=False)
```

**`backend/app/schemas/product.py`**:`ProductBase` / `Create` / `Update` / `Out` 4 个 Pydantic 模型,自动按字段生成。

**`backend/app/crud/product.py`**:`product_crud = CRUDBase[Product, ProductCreate, ProductUpdate](Product)` 一行。

**`backend/app/api/v1/endpoints/product.py`**:5 个标准接口(列表 / 创建 / 详情 / 更新 / 删除),全部要求 SuperUser。

**`frontend/src/api/product.ts`**:3 个 TS interface + 5 个函数。

**`frontend/src/views/product/index.vue`**:Element Plus 单页(列表表格 + 新增/编辑弹窗 + 删除确认)。

## 5.4 跑完后手动注册 5 步

脚本只生成新文件,**故意不改旧文件**(避免误改你的代码)。脚本会提示:

1. `backend/app/models/__init__.py` 加:

   ```python
   from app.models.product import Product
   ```

2. `backend/app/api/v1/router.py` 加:

   ```python
   from app.api.v1.endpoints.product import router as product_router
   api_router.include_router(product_router, prefix='/product', tags=['商品管理'])
   ```

3. `frontend/src/router/index.ts` 加:

   ```typescript
   { path: 'product', name: 'Product', component: () => import('@/views/product/index.vue'), meta: { title: '商品管理', icon: 'Goods' } }
   ```

4. `frontend/src/layouts/BasicLayout.vue` 加菜单项:

   ```vue
   <el-menu-item index="/product">
     <el-icon><Goods /></el-icon>
     <span>商品管理</span>
   </el-menu-item>
   ```

5. 数据库迁移:
   ```bash
   make db-migrate msg="add product"
   make db-upgrade
   ```

## 5.5 命名规范

| 场景   | 规则                                    | 例子                                |
| ------ | --------------------------------------- | ----------------------------------- |
| 模块名 | snake_case,以小写字母开头               | `order` ✅ / `Order` ❌ / `订单` ❌ |
| 字段名 | snake_case,非保留名                     | `price` ✅ / `id` ❌ / `class` ❌   |
| 标题   | 中文,会显示在菜单 / 路由 / 接口 summary | `订单管理` ✅                       |

## 5.6 实际场景示例

```bash
# 用户资料
python3 backend/scripts/add_module.py user_profile \
    --title "用户资料" \
    --fields "nickname:str,email:str,phone:str,avatar:str,bio:text"

# 文章(带开关 + 计数)
```

## 5.7 `--fields` 不够用?手动加

外键 / 索引 / 关系 / 唯一约束 / enum --fields 不支持,直接编辑生成的文件:

```python
# 在 model 里加索引
name: Mapped[str] = mapped_column(String(100), nullable=False, index=True)

# 加外键
user_id: Mapped[int] = mapped_column(ForeignKey("users.id"), nullable=False)

# 加关系
items: Mapped[list["OrderItem"]] = relationship(back_populates="order")
```

加完跑迁移:

```bash
make db-migrate msg="add fk + index"
make db-upgrade
```

## 5.8 二次跑覆盖

默认拒绝覆盖已存在的文件,防止误删你手动改的代码。确认要覆盖就加 `--force`:

```bash
python3 backend/scripts/add_module.py product --title "商品管理" --force
```

# §6 FAQ + 故障排查

## 6.1 FAQ

### Q: 三个 skill 有什么区别?

看 [§4.1 三种模式对比](#41-三种模式对比)。

### Q: 项目名起错了能改吗?

可以,但要改 8 处。建议:

```bash
# 删了重跑
rm -rf my-app
python3 /path/to/youzi-init-project/scripts/init.py my-app --only admin
```

### Q: 能改默认带的功能吗?

能。改 `templates/backend/app/models/user.py` 等文件,符号链接模式下自动生效。

### Q: 生成的代码能直接上线吗?

骨架可以,业务一定要改。生产清单看 [§4.4](#44-生产部署清单)。

### Q: 忘了 admin 密码?

```bash
cd my-app && make reset-admin
```

### Q: 加新业务模块后,接口 404?

按 [§5.4](#54-跑完后手动注册-5-步) 重新检查 5 处注册,最常见是漏了 `include_router(...)`。

### Q: 升级到新版本脚手架会破坏已有项目吗?

不会。`./install.sh update` 只刷 `~/.claude/skills/`,**已生成项目不受影响**。

### Q: `--fields` 里能加外键吗?

不能。手动加,见 [§5.7](#57--fields-不够用手动加)。

### Q: 字段名能是中文吗?

不能。字段名是 Python 标识符。

### Q: 多对多关系怎么生成?

`--fields` 不支持。先跑两个单表,再在 model 里手动加 `relationship(...)`。

### Q: `/yz-init-*` 跟 `python scripts/init.py <name>` 等价吗?

等价,只是入口不同:

- `scripts/init.py` 是 CLI,适合脚本 / CI / debug
- `/yz-init-*` 是 Claude 入口,自动问显示名 / 密码

## 6.3 术语速查
